Why this is one event, not {{ event.peak_nodes }} alerts {{ share }}% of the nodes that were reporting

When {{ share }}% of the nodes that were reporting turn unusual in the same two-minute check, independent faults are an unlikely explanation. The cause is more likely shared: the cluster being switched on or off, a power or cooling problem, a network or storage outage, or a large job starting everywhere at once.

HPCSentinel therefore recorded one event and held back the {{ event.peak_nodes }} individual alerts. If a node is still unusual after the event ends, it raises its own alert straight away, so a real fault underneath is not hidden.

Nodes that already had an alert before the event keep updating it as normal.
